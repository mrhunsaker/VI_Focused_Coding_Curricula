# Security Policy

## Scope

This repository is an educational textbook and mdBook publishing project. Reports may concern unsafe commands in instructional content, compromised dependencies or GitHub Actions workflows, exposed credentials, or vulnerabilities in project automation.

## Supported versions

Security fixes are applied to the current `main` branch. The published textbook is generated from that branch. Older commits and releases are not maintained as separate supported versions.

## Reporting a vulnerability

**Do not report suspected vulnerabilities in public GitHub Issues, Discussions, or Pull Requests.**

Use GitHub's private vulnerability reporting feature, if enabled: open this repository's **Security** tab and select **Report a vulnerability**. If private vulnerability reporting is unavailable, contact the repository maintainer privately through GitHub and request a secure channel. Do not include exploit details, credentials, or personal data in a public message.

Include, when safely possible:

- A concise description of the issue and its potential impact.
- The affected file, workflow, commit, or published page.
- Reproduction steps or a proof of concept that does not expose real secrets or harm systems.
- Any suggested mitigation.

## Response

The maintainer will acknowledge reports as soon as reasonably practical, investigate, and coordinate remediation and disclosure with the reporter. Please allow time for investigation and remediation before making details public. No guaranteed response-time commitment is made.

If a report is not a security vulnerability, it may be redirected to a public issue after confirming that doing so does not expose sensitive details.
